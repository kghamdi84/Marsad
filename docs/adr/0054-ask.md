# ADR 0054: Ask, questions answered by Claude through read-only tools

- Status: accepted (built; live once Khaled adds `ANTHROPIC_API_KEY` and `SUPABASE_ACCESS_TOKEN` and the first deploy runs)
- Date: 2026-11-28

## Context

Checklist item 8.1 asks for "Ask": Khaled types a question and gets an answer drawn from Marsad's own data, with citations. Khaled approved Anthropic API use on 2026-11-28 with small caps across all AI use: USD 1 a day and USD 10 a month. The rules that bind it: AI explains, code decides and calculates; every number in AI text is checked against the data it was given, else a template; untrusted text is wrapped in per-call random tags; provenance on every number; "data unavailable" beats a wrong number; no buy or sell advice; cost caps with a warning at 80%; RLS and only the publishable key in the browser.

ADR 0007 put AI generation in GitHub Actions because Edge Functions were unverified (item 5.2b). A question needs an answer within a minute, which a scheduled job cannot give, and the browser cannot hold an Anthropic key.

## Decision

- **Where:** a Supabase Edge Function, `supabase/functions/ask`, called by the page with the signed-in session. It is the first Edge Function, so its first deploy is also item 5.2b's platform check. The handler (`handler.ts`) has no Deno API in it and runs under Vitest with a fake model and a fake store; `index.ts` wires Deno, the Anthropic SDK (`npm:@anthropic-ai/sdk@1.8.0`) and supabase-js. Each function's `deno.json` maps `@marsad/core` to the generated `_shared/core` copy (ADR 0004); under Node the same name is the workspace package.
- **Who:** the function checks the caller's JWT with Supabase Auth, then `public.ask_is_owner()` (a security-invoker wrapper of `private.is_app_owner()`, callable by signed-in users only). Members (friends, ADR 0040) are told "owner only" before anything is read or spent.
- **Data access:** every tool queries Supabase with the caller's own JWT, so row-level security decides what Ask sees, exactly as on the pages. The service key is used for one write only: the `ai_usage` rows, which no signed-in user may write (the schema guards keep it that way).
- **Model and request:** Claude Sonnet 5.5 (`claude-sonnet-5-5`, ADR 0007) on the beta Messages endpoint with server-side fallback (`betas: ["server-side-fallback-2026-07-01"]`, `fallbacks: "default"`), adaptive thinking (the default; `thinking` is not sent), `output_config.effort: "medium"` (multistep tool use), no sampling parameters, no prefill, `tool_choice` auto (forced choice returns 400 on this model), `max_tokens` 8,000 per call, SDK timeout 45 s with one retry. The static system prompt carries `cache_control`, which with the fixed tool list before it forms the cached prefix; top-level `cache_control` caches the growing conversation between tool turns. Per-call material (the random tag) travels in tool results.
- **Tools (strict schemas, read-only):** `get_ticker_summary` (newest `ticker_daily_summary` row), `get_holdings` (open holdings), `get_company_research` (`company_research`), `get_regime` (latest `regime_daily`), `get_breadth` (latest `breadth_daily`), `get_filings` (two newest 10-K sections and 10-Q risk updates with SEC links and a 1,200-character excerpt), `get_alerts` (10 newest unsuppressed alerts). Code validates each input again (a ticker pattern) and a failed read goes back to Claude as a tool error ("Data unavailable"), never as a guess.
- **Facts, not raw rows:** `packages/core/src/ai/ask.ts` turns each row into citable facts: an id (F1 is Marsad's scope, then F2, F3, ...; documents D1, D2, ...), a label, the value in a declared unit (fractions become percentage points), the text Marsad formats for it, the source (table, job or vendor, formula version, session) and the as-of time, and the Marsad page it opens (Study view, Markets view, Portfolio view, Alerts) or the SEC URL. A missing figure is a fact with no value and its stored reason. Breadth shares are computed by code from the two stored counts. Vendor and filing text (Tauric's description and thesis, filing excerpts) are documents wrapped in a per-call random-ID tag (`untrusted.ts`); analyst ratings and theses are labelled third-party opinion.
- **Checks:** the final text must pass the figure verifier (`verify.ts`: every sentence cited, every figure equal to a cited fact within the precision written, units and direction agree, no em dash, no derived claims) and an advice-wording check ("you should", "consider selling", and similar). On failure the mismatches go back to Claude in an appended user turn and it rewrites once; a second failure, a `max_tokens` stop twice, an API error or a timeout gives the facts-only text (one sentence per fact, built by code). A `refusal` stops at once with the facts gathered so far. The verifier gained one rule here: a plain number that is part of a cited fact's label ("the 1-year return" for "return over 1 year") is accepted even when another fact happens to round to it.
- **Limits:** at most 4 tool turns (the next call gets `tool_choice: none`), 8 model calls per question, 110 s wall time, 500-character questions.
- **Spend:** `AI_CAPS` in `packages/core/src/ai/caps.ts` (USD 1 a day, USD 10 a month, warning at 80%); a lower cap in Settings (`user_settings`) wins, a higher one does not raise them. Before every call the function reads this UTC month's `ai_usage` (all jobs and Ask), adds this question's spend so far and refuses the call if one more typical call (USD 0.03) would pass a cap. At the cap before the first call the reply is "AI limit reached for today" or "this month" with no call. Each call is priced from its usage fields (`cost.ts`, which now also prices `claude-sonnet-5`, the fallback model; the `ai_usage` model check allows it) and written to `ai_usage` (`job = 'ask'`).
- **Log:** `public.ask_log` (personal, owner-only, select and insert only, no anon): question, answer, citations, verified, model, USD, state, as-of. The page reads its history from it.
- **Not configured:** without `ANTHROPIC_API_KEY` (or without the service key to record spend) the function answers 503 "not configured" and spends nothing; the page says "Ask is not configured yet", also when the function is not deployed.
- **Deploy:** `deploy-functions.yml`, manual, function `ask` by default: checks the `SUPABASE_ACCESS_TOKEN` secret, builds the core copy, runs `deno check`, then `supabase functions deploy ask --use-api`. CI's `edge-core` job also runs `deno check` on the function.

## Consequences

- No figure reaches Khaled unless code matched it to a stored value he can open; the worst case is a correct list of facts without prose.
- Spend is bounded per question (8 calls of at most 8,000 output tokens, priced conservatively) and per day and month across all AI use. A failed `ai_usage` write is logged loudly; the next question would under-count that one answer's spend.
- Known limits: the verifier cannot see numbers spelled as words (the prompt forbids them) or a coincidence between two cited facts of the same unit and value; the advice check is a word list. Questions about data Marsad does not store get "data unavailable" or the facts-only text.
- Not verified on the platform until the first deploy: bundling of the `_shared/core` copy through the import map with `--use-api`, the gateway's JWT check, and real answers. That is item 5.2b and the live half of 8.1.
